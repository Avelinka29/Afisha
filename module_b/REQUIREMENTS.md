# Соответствие заданию ProfSkills

## Общие требования

- [x] Модуль А находится в `module_a`, модуль Б — в `module_b`, инструкция — в корневом README.
- [x] Все действия клиента и получение данных выполняются через PHP API `/api`.
- [x] Данные сохраняются в MySQL; клиент не заменяет серверные проверки прав.
- [x] Адаптивные страницы для компьютера, планшета и телефона.
- [x] Проверка в Google Chrome, в том числе ширины 320, 390, 768 и 1440 px.
- [x] Шапка с логотипом, навигацией, уведомлениями и меню пользователя.
- [x] «Мои мероприятия» видны только представителям; есть проверка прямого перехода.
- [x] Футер с контактным email; указан учебный статус проекта.
- [x] Состояния загрузки, пустые списки, обработка ошибок, повторная загрузка, диалоги подтверждения и сообщения об успехе.
- [x] Готовая копия клиента в `module_b/dist`, команда её подготовки в README.

## Афиша — `/`

- [x] Сетка карточек: обложка, название, сообщество, категория, дата/время, место, формат.
- [x] Число регистраций, обе реакции, свободные места и прогресс заполненности.
- [x] Фильтры: категория, Комьюнити, формат, диапазон дат, только предстоящие.
- [x] Поиск по названию/описанию, сортировка по дате и популярности.
- [x] Пагинация при превышении размера страницы.
- [x] Отметки реакций и регистрации вошедшего студента.

## Карточка — `/events/:id`

- [x] Полное описание, Комьюнити, категория, начало/окончание, место, формат и вместимость.
- [x] «Пойду», отмена записи с подтверждением и обновление счётчиков.
- [x] Отдельные переключаемые реакции «Нравится» и «Интересно».
- [x] Отменённые, начавшиеся, завершённые события и отсутствие свободных мест.
- [x] Причина отмены, недоступность черновиков посторонним.
- [x] Сообщения для ALREADY_REGISTERED, EVENT_FULL, EVENT_STARTED, EVENT_CANCELLED, USER_BLOCKED; переход на вход при 401.
- [x] Представителю своего Комьюнити доступна ссылка управления.

## Аккаунт

- [x] `/register`: имя, email, специальность, курс 1–4, пароль от 8 символов; клиентская и серверная валидация.
- [x] Подтверждение email по одноразовой ссылке, создание сессии и переход на главную.
- [x] `/login`: вход и сообщения о неверных данных, неподтверждённой почте, блокировке.
- [x] `/password-reset`: запрос письма и форма нового пароля по токену.
- [x] `/me`: профиль, роль, Комьюнити с флагом верификации.
- [x] Редактирование имени, специальности, курса и аватара; email/роль не редактируются.
- [x] Смена пароля с текущим паролем и подтверждением, сообщение об успехе.
- [x] Выход с уничтожением сессии, очисткой состояния клиента и переходом на `/`.

## Кабинет студента

- [x] `/me/registrations`: предстоящие/прошедшие, даты, статусы active и cancelled_by_organizer.
- [x] Отмена своей регистрации с подтверждением только до начала.
- [x] Прошедшие активные регистрации считаются посещёнными; явка не отмечается.
- [x] `/me/reactions`: события, тип и дата реакции; снятие прямо из списка.
- [x] `/me/notifications`: иконка типа, текст, дата и переход к событию из payload.event_id.
- [x] Дополнительно реализованы отметка о прочтении и индикатор непрочитанных в шапке.

## Кабинет представителя

- [x] `/me/events`: все события своих верифицированных Комьюнити, включая черновики.
- [x] Фильтр draft/published/cancelled, даты, регистрации и счётчики реакций.
- [x] Редактирование, публикация черновика, отмена с причиной, удаление только черновика, переход к участникам.
- [x] `/me/events/new`, `/me/events/:id/edit`: все поля из ТЗ, выбор только верифицированных Комьюнити.
- [x] Проверка дат: окончание позже начала; новое начало и публикация — в будущем. При редактировании исторического события допускается сохранить исходную дату без переноса.
- [x] «Сохранить черновик» и «Опубликовать»; редактирование опубликованного сохраняет его текущий статус.
- [x] Обложка по ссылке или загрузка с предпросмотром.
- [x] `/me/events/:id/participants`: имя, специальность, курс, время регистрации, статус, пагинация и экспорт .txt.

## Серверные правила и уведомления

- [x] Один пользователь может представлять несколько Комьюнити; верификацией управляет администратор.
- [x] Студент не создаёт события; представитель не управляет чужим Комьюнити.
- [x] Уникальность регистрации и каждой реакции обеспечивается базой.
- [x] Транзакция и блокировка события защищают последнее свободное место.
- [x] Запись и её отмена запрещены после начала; запись запрещена на отменённые и заполненные события.
- [x] registration_confirmed, event_cancelled, event_changed, event_full.
- [x] event_reminder за 24 часа и 1 час, защита от дублей, отдельный планировщик.
- [x] SMTP-отправка подтверждения/восстановления при настройке .env; без пароля — тестовый журнал `module_a/storage/mail.log`. Инструкция и аккаунты в README.
- [x] Единый JSON ошибок, HTTP-коды, пагинация списков, Postman-коллекция с описанием каждого запроса.
- [x] Миграция SQL и сидер: пользователи, справочники, 29 событий, регистрации, реакции, уведомления и обложки.

## Администрирование — `/admin`

- [x] Список пользователей, блокировка и разблокировка.
- [x] Выдача/отзыв верификации для пары «пользователь — Комьюнити».
- [x] Создание, изменение, удаление Комьюнити и категорий.
- [x] Модерация: отмена опубликованного события с причиной и уведомлением участников.

Email-рассылка уведомлений об особо важных событиях опциональна по ТЗ; обязательные уведомления реализованы в кабинете. Аутентификация сессионная, поэтому refresh-токены и `/api/auth/refresh` не требуются.
